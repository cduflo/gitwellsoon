# V3.1 Design — Permission-Surface Overhaul

Status: DESIGN, decision-ready. No code in this change.
Scope source: CHANGELOG.md "Deferred to 3.1" + v3.0 session analysis (2026-08-28).

## 0. Decision summary

**Recommendation: Option (c-modified) — ship 3.1 with broad matches kept; treat the 3.2 narrowing as gated, not scheduled.**

3.1 = minimal service worker + granted-origins-as-truth migration + one-click popup (storage/tabs permissions and all their UI machinery deleted) + a low-key in-page nudge that converts heuristic-matched GHE users into pinned origin grants. Zero warning delta, zero silent breakage, large cruft deletion.

The narrowing (3.2) is deliberately **not scheduled**, because of a rollback asymmetry found during this design (§7): un-narrowing re-adds an all-sites match pattern, which is a warning *increase* — Chrome disables the extension for every user until they re-approve. Narrowing is cheap to ship and catastrophic to revert, so it needs a compelling trigger (store-policy pressure, or high confidence the heuristic cohort has converted), not a calendar.

## 1. The crux: the heuristic-only GHE cohort

In 2.x/3.0, a user on `github.company.com` or `git.company.com` works with **zero popup interaction**: the broad path-scoped matches (`manifest.json:24-27`) inject everywhere, and `isGitHubSite()` (`content.js:34-42`) passes on the `github.`/`ghe.`/`git.*` substrings. These users have **no granted origin** — nothing to migrate. Chrome match patterns cannot express `github.*` (host wildcards are leftmost-label only), so no manifest can keep them after narrowing.

Adjudication against the stated priorities:

| Option | Silent users | Warning reduction | Cruft | Update seamlessness |
|---|---|---|---|---|
| (a) keep broad matches forever | safe | none, ever | popup still slims | silent |
| (b) narrow now + migrate grants | **breaks heuristic cohort silently** — the 1-star failure mode again | immediate | popup slims | silent (shrink) but see §7 rollback trap |
| (c) staged: 3.1 broad + nudge, 3.2 narrow | safe in 3.1; 3.2 breaks whoever never converted | deferred | +nudge (~30 lines) | silent both hops |

(b) is eliminated: the cohort size is unknowable (no telemetry, 572 users), and "worked before, broken after update, no error shown" is precisely what earned the 1-star review. (a) forfeits the goal permanently. (c) keeps every current user working, starts converting the heuristic cohort to explicit grants, and leaves narrowing as a decision with an evidence bar rather than a promise.

Bonus found while verifying migration (§5): 3.1 *fixes* a real 2.x bug — with the storage permission off, adding a host granted the origin but never persisted it (`popup.js:292-296` persists "only if storage permission is enabled"), so the feature silently never worked on that host unless it was heuristic-matched. Origin-as-truth repairs those users.

## 2. Manifest (3.1)

```json
{
  "name": "Git Well Soon",
  "version": "3.1.0.0",
  "manifest_version": 3,
  "permissions": ["scripting", "activeTab"],
  "optional_host_permissions": ["https://*/*"],
  "background": { "service_worker": "worker.js" },
  "action": { "default_title": "Git Well Soon", "default_popup": "popup.html" },
  "content_scripts": [ /* UNCHANGED from 3.0 — github hosts + broad path patterns */ ]
}
```

Removed: `optional_permissions: ["storage", "tabs"]` (and all `chrome.storage` / `chrome.tabs.query`-via-tabs-permission usage).
Added: `scripting` (register dynamic content scripts on granted origins), `activeTab` (popup reads current tab host + reloads it). Both are warning-free (V-1, V-2 in §9).

3.2 manifest (if ever triggered): identical except `content_scripts.matches` drops the four wildcard path patterns, keeping only `https://github.com/*`, `https://*.github.com/*`, `https://*.ghe.com/*`.

## 3. Service worker (`worker.js`, ~25 lines)

Responsibilities — exactly two events, no state:

- `onInstalled` + `onStartup`: `permissions.getAll()` → for each granted `https://<host>/*` origin that isn't a built-in GitHub host (reuse the classifier logic from `popup-lib.js:96`), `scripting.unregisterContentScripts()` then `registerContentScripts([{id, matches:[origin-with-diff-paths], js:['granted-marker.js','content.js'], runAt:'document_start', persistAcrossSessions:true}])`. Re-registration on every install/update event because dynamic registrations do not survive extension updates.
- Nothing else.

Deliberately does NOT: handle messages, track tabs, use webNavigation, use storage, use alarms, hold any state. The popup performs its own registration after a grant (chrome.scripting is available to popup contexts), so no worker round-trip exists in any user flow. If the worker is dead when a page loads, nothing breaks for already-registered scripts (registrations persist across browser sessions).

**granted-marker.js** (1 line: `window.__gwsGranted = true;`): injected only via dynamic registration, ahead of content.js. This is how content.js distinguishes "running under an explicit grant" from "running via broad manifest match + heuristic" without messaging the worker — the isolated world is shared per-extension, so the flag is visible to content.js.

## 4. Popup spec (~60 lines JS target)

States, derived from the active tab via `activeTab` (granted by opening the popup — V-1):

1. **Non-https page** (chrome://, file:, newtab): neutral text "Works on GitHub PR diff pages." No button.
2. **Built-in GitHub host** (github.com / *.github.com / *.ghe.com): "✓ Active on <host>". No button.
3. **Granted custom host**: "✓ Active on <host>" + **Disable** button → `permissions.remove(origin)` + `scripting.unregisterContentScripts({ids:[id]})` + reload tab.
4. **Ungranted custom host**: "Enable on <host>" button → `permissions.request(origin)` → register script (same spec as worker) → reload tab. Heuristic-matched hosts (currently working in legacy mode) show state 4 phrased as "Pin permission for <host>" so the nudge (§6) has a landing spot.
5. Below the status: the granted-hosts list (`listGrantedHosts`, ported from `popup-lib.js:68-103`) with per-row Remove — kept because chrome://extensions "Site access" is the only alternative and it's undiscoverable.

Machinery that dies with the storage/tabs removal: both permission switches and `toggleSwitch` (`popup.js:233-268`), free-text host input + `parseHostInput` + clear button (`popup.js:270-324`, `popup-lib.js:2-21`), pending-add persistence (`popup.js:66-103,197-213` — it existed only because the permission prompt could close the popup mid-add; the one-click flow re-derives everything from `permissions` state on reopen, so an interrupted grant self-heals with no stored pending marker), storage load/save (`popup.js:37-63`), prefill (`popup.js:216-231`). `scheduleReloadIfActiveMatches` (`popup-lib.js:141-154`) survives, driven by activeTab instead of the tabs permission.

No free-text host entry means a host can only be enabled while visiting it. Accepted: that is the natural moment, and it eliminates the entire parse/validate/duplicate error surface (`test/popup-lib.parseHostInput*.test.js`, `test/popup-ui.add-duplicate.test.js`).

## 5. Migration from 3.0 (on update, in `onInstalled`)

Granted origins are the sole source of truth; `extraHosts` storage dies unread.

No-data-loss verification against the 2.x/3.0 code:
- The add flow persists to `extraHosts` **only after** `permissions.request` succeeds (`popup.js:285-296`); a denied grant is never persisted (`popup.js:286-290`).
- The interrupted-prompt path persists only after `permissions.contains` confirms the grant (`popup.js:200-206`).
- Removal revokes the grant and then the storage entry together (`popup.js:118-126`), and `syncHostsWithPermissions` prunes storage entries whose grants vanished (`popup-lib.js:115-126`).

Therefore every *functioning* custom host necessarily has a granted origin, and origin grants survive extension updates. The only `extraHosts` entries without grants are already-dead ones (grant revoked externally via chrome://extensions — the content script stopped injecting the moment the grant vanished, storage entry notwithstanding). Losing dead entries is not data loss. Fallback design: none needed.

Sequence: update installs → `onInstalled` fires → worker registers scripts for all granted non-built-in origins → GHE pages work on next load. Known race: a page loaded in the instant between update and `onInstalled` completing misses injection once (§9 V-5); next navigation self-heals.

## 6. The nudge (heuristic hosts → pinned grants)

Where: content.js, only when ALL hold — `!window.__gwsGranted` (no explicit grant), `isGitHubSite()` heuristic passed, host is not a built-in GitHub host, page is a relevant diff view, and `localStorage['gws-pin-nudge'] !== 'dismissed'` (page-domain localStorage; no extension storage exists in 3.1).

What: one small dismissible banner, once per host: "Git Well Soon works here via pattern-matching. Click the extension icon to pin permission for this host." Dismiss = never again on that host. No animation, no repeat, no links — the popup (state 4) does the actual grant.

Why bother if 3.2 may never ship: it repairs the §1-bonus bug cohort, and every conversion shrinks the population at risk should narrowing ever be triggered. Rollback for the nudge alone: it renders only on `isGitHubSite()` hosts on diff paths, so a false-positive banner on an unrelated site implies the heuristic *and* path both matched — the same condition under which 2.x already redirected that site's URLs, i.e., no new exposure class. If reports still arrive, a point release deletes the banner block.

## 7. Store submission and the rollback asymmetry

- 3.1: warning delta **none** (scripting/activeTab warning-free, removals prompt nothing — V-2/V-3). Silent auto-update. Dashboard justifications: `scripting` — "registers the content script only on GitHub Enterprise origins the user explicitly grants via the popup"; `activeTab` — "reads the current tab's hostname to offer one-click enable and reloads that tab after enabling"; host permission — unchanged text from 2.x.
- 3.2 (if triggered): warnings shrink from "read and change all your data on all websites" (current listing text to be confirmed — V-4) to the three GitHub hosts. Silent update.
- **Asymmetry**: reverting 3.2 means re-adding a wildcard-host match — a warning increase — which Chrome handles by **disabling the extension for every user until manually re-approved**. A 3.2 rollback is therefore worse than the bug it fixes. Consequence: 3.2 ships only when the residual heuristic cohort is believed near-zero or an external forcing function exists, and it should ship as `4.0.0.0` with loud listing notes. Until then (c) behaves like (a), by design.
- 3.2 go/no-go evidence bar (honest version — we have no telemetry): ≥3 months of nudge exposure, zero GHE-related issues/reviews in that window, and a re-check that CWS policy still tolerates the broad matches (if CWS ever forces the issue, that is the trigger).

## 8. Test plan

Die with their features: `popup-ui.storage-toggle`, `popup-ui.tabs-toggle`, `popup-ui.pending-add`, `popup-ui.add-duplicate`, `popup-ui.add-denied-permission` (denial becomes a trivial no-op state), `popup-ui.clear-button`, `popup-ui.prefill-reload-on-tabs`, `popup-lib.parseHostInput` + `.edge`, `popup-lib.syncHosts`, `allowlist.test.js` (extraHosts gating → replaced).

Port: `popup-lib.listGrantedHosts` (unchanged logic), `popup-lib.reload` + `.edge` (`scheduleReloadIfActiveMatches` survives), `popup-ui.remove-reload` (adapted to the Disable flow), all of `content.test.js` / `spa-navigation.test.js` / `isAllowedHost` (content core untouched except gating).

New: worker registration unit (mock `chrome.scripting` + `permissions.getAll`: registers non-built-in grants, idempotent re-run, skips built-ins); migration unit (grants present → registered; extraHosts ignored entirely); marker-gating unit (`__gwsGranted` true ⇒ enabled regardless of heuristic; false + heuristic ⇒ enabled + nudge-eligible; false + non-GitHub-like ⇒ disabled); nudge unit (render conditions, dismiss persistence); popup state-machine unit (states 1–5 from a mocked tab + permissions); e2e via the README ngrok flow — grant through popup ⇒ injection after reload, extension reload (update simulation) ⇒ `onInstalled` re-registration still injects; e2e popup states on github.com.

## 9. Open verification items (check in real Chrome before shipping — none are settled by docs memory)

- **V-1**: `activeTab` + popup open ⇒ `tabs.query({active:true,currentWindow:true})[0].url` populated without the `tabs` permission. Verify: unpacked build, log from popup.
- **V-2**: `scripting` and `activeTab` produce no install/update warning. Verify: fresh unpacked install prompt + `chrome://extensions` details.
- **V-3**: Removing granted optional permissions (`storage`, `tabs`) from the manifest on update is silent — no disable, no prompt. Verify: install 3.0 unpacked, grant both, swap in 3.1 manifest, reload extension.
- **V-4**: Current CWS listing actually displays the all-sites warning for the wildcard path matches. Verify: listing page "Permissions" section or fresh store install on a clean profile.
- **V-5**: `onInstalled` timing after a store update — confirm registrations exist before a same-instant page load, or accept the one-page-load miss. Verify: unpacked reload + immediate navigation.
- **V-6**: `registerContentScripts` with `persistAcrossSessions:true` from the **popup** context persists identically to worker-registered scripts. Verify: register via popup, restart Chrome, check `getRegisteredContentScripts()`.

## 10. Recommendation, risks, size

**Recommended: (c-modified)** — 3.1 as specced (broad matches kept, worker + migration + marker + slim popup + nudge), 3.2 gated behind §7's evidence bar and possibly never shipped. It is the only option that simultaneously honors "never break silent users" and makes future narrowing *possible*, while deleting more code than it adds.

Three riskiest assumptions:
1. V-1 (activeTab URL access from popup) — the whole popup design rests on it; fallback if wrong is re-adding optional `tabs`, which is warning-free but resurrects a toggle.
2. V-3 (silent optional-permission removal) — if wrong, 3.1 is no longer a silent update and should be re-sequenced.
3. Migration completeness (§5) rests on code-reading of 2.x flows; a 2.0-era popup version that persisted before granting would break the "every functioning host has a grant" invariant — mitigated by checking `git log -p popup.js` for the add-flow history during implementation.

Size: touched — `manifest.json`, `worker.js` (new), `granted-marker.js` (new), `popup.html` (rewrite), `popup.js` (~325→~60), `popup-lib.js` (~172→~70), `content.js` (+~40 gating/nudge), `scripts/build.js` (copy list), `CHANGELOG.md`, `README.md`. Tests: ~11 files deleted, ~5 ported, ~7 new. Estimate: 1–2 days including the ngrok e2e pass and the V-1..V-6 checks.
